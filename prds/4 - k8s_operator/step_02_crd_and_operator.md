# Step 2 — `BlueprintRun` CRD + operator core (submit + status)

**Goal:** The resource interface itself: a generated `BlueprintRun` CRD whose spec can
never drift from the wire protocol, and a kopf operator that turns resource creation
into daemon runs and writes status back. End state: `kubectl apply -f blueprintRun.yaml`
→ run executes → `kubectl get blueprintRun` shows live phase/spend/status.

**Depends on:** step 1. **Blocks:** step 3.

## 2.2 CRD generation — `crd.py`

- `BlueprintRun.spec` schema derives from the split PRD's `SubmitRunRequest`
  (`model_json_schema()`), minus `blueprint_path`/`run_dir` (meaningless in-cluster),
  plus `blueprintRef: {configMap: str, key: str}`. Status schema is hand-authored from
  `RunRecord`'s shape + `observedGeneration`/`runId` [L1].
- Emit structural-schema-compliant OpenAPI v3 (`x-kubernetes-preserve-unknown-fields`
  nowhere; explicit `type: object` at every level — apiextensions rejects schemaless
  nodes). Unit test asserts the emitted schema validates as a structural schema.
- The generator is the **only** way the manifest changes; CI runs it and diffs.
  Document the rule: protocol model changes (additive, per the split PRD's evolution
  rules) require `task operator:crd` and re-review of the diff.
- Group `goblin.dev`, version `v1`, kind `BlueprintRun`, namespaced; `status` as a
  subresource (required for clean status patches without spec conflicts) [S3].
- Printer columns for UX: `kubectl get blueprintRuns` shows Phase, Age, Spend —
  `additionalPrinterColumns` from status fields.

## 2.3 Handlers — `operator.py`

- **`@kopf.on.create("goblin.dev", "v1", "blueprintruns")`:**
  resolve the blueprint (`spec.blueprintYaml` inline, or read the referenced ConfigMap
  key — RBAC grants ConfigMap read in the operator's namespace scope), build
  `SubmitRunRequest`, submit with **idempotency key `<metadata.uid>:<metadata.generation>`**
  (the daemon dedupes — a re-fired create for the same generation returns the existing
  run, never a double-run [L1]); patch `status: {runId, phase: Pending,
  observedGeneration}`.
- **`@kopf.timer("goblin.dev", "v1", "blueprintruns", interval=config.poll_interval,
  sharp=True)`:** skip terminal CRs; `get_run(status.runId)` → map to status fields
  (`phase`, `phases` summary, `spend`, `error`, timestamps) → patch only on change
  (idempotent, conflict-retry on 409); emit a k8s Event on each phase transition
  (`Normal: RunPhaseCompleted` / `Warning: RunFailed`) [S1].
- Daemon unreachable → `kopf.TemporaryError` with backoff (kopf retries the handler; no
  crash loops) [S1].
- Handler bodies stay thin: pure mapping functions (`spec_to_request`,
  `runrecord_to_status`) unit-tested without kopf; handlers are wiring.

## 2.4 Operator deployment — `manifests/operator.yaml`

- ServiceAccount + Role/ClusterRole: `blueprintruns` get/list/watch/patch (+status
  subresource), `configmaps` get, `events` create. Namespaced Role preferred; document
  the ClusterRole variant.
- Deployment: single replica; env `GOBLIN_OPERATOR_DAEMON_URL` + token from the same
  Secret as the daemon; `kopf run --standalone -m goblin_operator.operator` (standalone
  = no peering objects in V1; step 3 documents peering for HA) [S1].
- Probes: kopf has no built-in health endpoint — use a trivial `livenessProbe` on the
  process (exec `pgrep`/proc check) or document the tradeoff and rely on restart policy;
  decide in implementation, record the choice here.

## 2.5 Tests

- **Unit (default CI):** `spec_to_request` / `runrecord_to_status` mapping incl.
  `blueprintRef` resolution; handler functions called directly with a mocked
  `DaemonClient` (submit called with the right idempotency key; status patched only on
  change; TemporaryError on connection failure); CRD generator golden-file + structural
  validation.
- **Import guard:** assert `kopf` and `kubernetes` absent from `sys.modules` after
  importing `goblin.cli`, `goblin.client`, `goblin_daemon` (README F/non-functional:
  zero coupling into existing packages).
- **kind e2e (gated, extends step 1):** apply CRD + operator →
  `kubectl apply` a `BlueprintRun` (LLM-free blueprint [L5]) →
  `kubectl wait`/poll for `status.phase == Completed` with phase summary + spend →
  ConfigMap-referenced blueprint variant → re-apply same CR (same uid/generation) →
  assert no second run (idempotency).
